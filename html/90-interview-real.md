### R1. 什么是 HTML 语义化？为什么要语义化？

- **难度**: junior
- **标签**: 语义化
- **来源倾向**: 国内前端基础必问

**答案**

语义化是根据内容含义选择元素，例如导航用 `nav`、主内容用 `main`、按钮用 `button`。它让读屏器、搜索引擎和浏览器都能理解页面结构，同时带来原生交互和更好的代码可读性。

详见 [10-junior-qa Q7/Q8](10-junior-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：语义化是让元素表达内容含义。
2. 关键机制：语义映射到无障碍树，也影响浏览器默认行为。
3. 注意点：重点不是少写 div，而是选对元素。
4. 可追问时补充：button 和 a 的区别。

**常见追问**

- 语义化和 SEO 的关系？→ 帮助搜索引擎理解内容，但不保证排名。

### R2. HTML5 有哪些新特性？

- **难度**: junior
- **标签**: HTML5
- **来源倾向**: 传统高频题

**答案**

常见回答：

- 结构语义元素：`header`、`nav`、`main`、`article`、`section`
- 表单增强：`email`、`date`、`required`、`pattern`
- 媒体：`audio`、`video`、`track`
- 图形：`canvas`、内联 SVG
- 存储和 API：`localStorage`、History API、Web Worker 等（严格说很多属于 Web API）

现代回答要补充：HTML 现在是 Living Standard，持续增加 `dialog`、Popover、Invoker Commands 等能力。

**口述模板（30–60 秒）**

1. 一句话结论：HTML5 增强了语义、表单、媒体和 Web 应用能力。
2. 关键机制：浏览器提供更多原生元素和 API。
3. 注意点：现在不再按 HTML5 固定版本理解。
4. 可追问时补充：近期的 dialog、Popover 和 command。

**常见追问**

- Application Cache 还用吗？→ 已废弃，离线能力用 Service Worker。

### R3. `script` 的 `async` 和 `defer` 有什么区别？

- **难度**: mid
- **标签**: script
- **来源倾向**: 前端必问

**答案**

二者都并行下载。`async` 下载完立即执行、不保证顺序；`defer` 等 HTML 解析完成后，按文档顺序在 `DOMContentLoaded` 前执行。

详见 [20-mid-qa Q3](20-mid-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：async 先到先执行，defer 解析后按顺序执行。
2. 关键机制：都不阻塞下载阶段的 HTML 解析。
3. 注意点：async 不适合有依赖的脚本。
4. 可追问时补充：module 默认 defer。

**常见追问**

- 内联 script 写 defer 有用吗？→ 经典内联脚本无效。

### R4. CSS 和 JS 会阻塞页面渲染吗？

- **难度**: mid
- **标签**: 关键渲染路径
- **来源倾向**: 浏览器原理高频

**答案**

CSS 阻塞渲染；同步 JS 阻塞 HTML 解析；JS 执行前还可能等待前面 CSS 构建 CSSOM。优化方式包括关键 CSS、`defer`、拆分非关键资源。

详见 [20-mid-qa Q2](20-mid-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：CSS 卡首绘，同步 JS 卡解析。
2. 关键机制：JS 可能读写 DOM 和样式。
3. 注意点：CSS 会间接阻塞后续 JS。
4. 可追问时补充：预加载扫描器。

**常见追问**

- 为什么 CSS 放 head、JS 放 body 底部？→ 尽早构建 CSSOM，同时减少脚本阻塞；现代更推荐 head 中 defer。

### R5. `preload` 和 `prefetch` 有什么区别？

- **难度**: mid
- **标签**: Resource Hints
- **来源倾向**: 性能优化高频

**答案**

`preload` 用于当前页面很快需要的关键资源，优先级高；`prefetch` 用于未来导航可能使用的资源，优先级低。二者只加载，不执行。

详见 [20-mid-qa Q6](20-mid-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：preload 管当前页，prefetch 管下一页。
2. 关键机制：提前进入网络队列或空闲下载。
3. 注意点：preload 必须正确设置 as。
4. 可追问时补充：preconnect 和 dns-prefetch。

**常见追问**

- preload 太多有什么问题？→ 抢占关键带宽，可能反而拖慢 LCP。

### R6. `DOMContentLoaded` 和 `load` 有什么区别？

- **难度**: mid
- **标签**: 生命周期
- **来源倾向**: 高频基础

**答案**

`DOMContentLoaded` 表示初始 HTML 解析完成且 defer 脚本已执行；`load` 还要等待图片、样式、iframe 等资源加载完成。

详见 [20-mid-qa Q9](20-mid-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：DCL 看 DOM，load 看全部资源。
2. 关键机制：defer 在 DCL 前执行。
3. 注意点：async 不保证在 DCL 前。
4. 可追问时补充：现代性能更看 Web Vitals。

**常见追问**

- 页面关闭时上报用哪个事件？→ `visibilitychange` / `pagehide` + `sendBeacon`。

### R7. 从输入 URL 到页面显示，HTML 解析阶段发生了什么？

- **难度**: senior
- **标签**: 浏览器原理
- **来源倾向**: 高级前端常见长链路题

**答案**

聚焦 HTML 阶段：

1. 响应字节按编码解码
2. HTML 分词和建树，增量生成 DOM
3. 遇到 CSS 下载并构建 CSSOM
4. 遇到同步脚本暂停解析
5. 预加载扫描器提前发现资源
6. DOM + CSSOM 形成渲染树，布局、绘制、合成

详见 [20-mid-qa Q1/Q5](20-mid-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：HTML 被增量解析成 DOM，与 CSSOM 合成渲染树。
2. 关键机制：同步脚本暂停解析，CSS 阻塞渲染。
3. 注意点：预加载扫描器能提前发现资源。
4. 可追问时补充：LCP 优化与资源优先级。

**常见追问**

- DOM 构建完一定已经显示页面了吗？→ 不一定，可能还在等待 CSS、字体或渲染时机。

### R8. 你如何理解无障碍？前端能做哪些事？

- **难度**: mid
- **标签**: a11y
- **来源倾向**: 中高级越来越常问

**答案**

无障碍是让不同能力、设备和环境下的用户都能感知、理解、操作页面。前端重点：

- 语义化 HTML
- 可访问名称
- 键盘操作和焦点管理
- 图片和媒体替代内容
- 表单错误关联
- 颜色对比度
- 动态内容播报

详见 [20-mid-qa Q11–Q18](20-mid-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：先用对 HTML，再补 ARIA。
2. 关键机制：浏览器生成无障碍树给辅助技术。
3. 注意点：键盘、焦点和名称最容易出问题。
4. 可追问时补充：自动化扫描加人工测试。

**常见追问**

- ARIA 越多越好吗？→ 不是，错误 ARIA 比没有 ARIA 更糟。

### R9. ARIA 是什么？什么时候用？

- **难度**: mid
- **标签**: ARIA
- **来源倾向**: a11y 高频

**答案**

ARIA 用于补充原生 HTML 无法表达的角色、状态和属性。能用原生元素时不用 ARIA。ARIA 不提供行为，例如 `role="button"` 仍需手动支持键盘。

详见 [20-mid-qa Q12](20-mid-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：ARIA 补语义，不补行为。
2. 关键机制：影响无障碍树。
3. 注意点：No ARIA is better than bad ARIA。
4. 可追问时补充：Tabs、Combobox 等复杂组件需要 ARIA 模式。

**常见追问**

- `aria-hidden` 能用于可聚焦元素吗？→ 不应该，会导致焦点落到读屏不可感知的元素上。

### R10. `button` 和 `a` 有什么区别？

- **难度**: junior
- **标签**: 语义, 交互
- **来源倾向**: 实战代码审查题

**答案**

`a` 用于导航，`button` 用于执行动作。用 `a href="#"` 当按钮、用 `span` 当按钮都会造成语义和键盘问题。

详见 [20-mid-qa Q17](20-mid-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：跳转用链接，动作用按钮。
2. 关键机制：两者默认行为和键盘交互不同。
3. 注意点：不要按外观选元素。
4. 可追问时补充：SPA 路由仍用链接。

**常见追问**

- 表单中的 button 默认是什么？→ `submit`。

### R11. `img` 的 `alt` 和 `title` 有什么区别？

- **难度**: junior
- **标签**: 图片, a11y
- **来源倾向**: 基础题

**答案**

`alt` 是图片替代文本，用于图片不可见、读屏和搜索理解；`title` 是补充提示，常显示为 tooltip，不可靠且触屏和键盘用户不一定能获取。

详见 [10-junior-qa Q16](10-junior-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：alt 是替代内容，title 是补充提示。
2. 关键机制：alt 参与无障碍和图片失败展示。
3. 注意点：装饰图使用空 alt。
4. 可追问时补充：链接图片 alt 描述目标。

**常见追问**

- alt 能写 SEO 关键词堆砌吗？→ 不应该，按真实图片含义描述。

### R13. 怎么防止 HTML 中的 XSS？

- **难度**: mid
- **标签**: XSS
- **来源倾向**: 安全必问

**答案**

不要把不可信内容当 HTML 插入；普通文本用 `textContent`；按上下文转义；富文本白名单清洗；URL 协议白名单；CSP 和 Trusted Types 兜底。

详见 [20-mid-qa Q23/Q24](20-mid-qa.md)、[30-senior-qa Q17–Q19](30-senior-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：防 XSS 的核心是数据不能变成代码。
2. 关键机制：按输出上下文编码。
3. 注意点：富文本用成熟白名单清洗库。
4. 可追问时补充：CSP 是兜底不是替代。

**常见追问**

- React 能完全防 XSS 吗？→ 默认插值安全，危险 API 和 URL 仍需处理。

### R14. iframe 有哪些优缺点？怎么保证安全？

- **难度**: mid
- **标签**: iframe
- **来源倾向**: 微前端 / 第三方嵌入常见

**答案**

优点是隔离强、技术栈独立；缺点是性能开销、通信复杂、弹窗和路由同步难、SEO 差。安全上使用 `sandbox`、`allow`、CSP `frame-src` / `frame-ancestors`，postMessage 校验 origin 和消息结构。

详见 [20-mid-qa Q25/Q26](20-mid-qa.md)、[30-senior-qa Q20/Q21](30-senior-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：iframe 用性能和体验换隔离。
2. 关键机制：独立浏览上下文。
3. 注意点：权限最小化，通信要校验。
4. 可追问时补充：微前端选型。

**常见追问**

- 跨域 iframe 怎么自适应高度？→ 子页面计算高度后 postMessage 通知父页面。

### R15. 什么是点击劫持？怎么防？

- **难度**: mid
- **标签**: 安全
- **来源倾向**: Web 安全高频

**答案**

攻击者把目标页面透明嵌入 iframe，诱导用户点击。使用 CSP `frame-ancestors` 或 `X-Frame-Options` 响应头防止被不可信页面嵌入。

详见 [20-mid-qa Q26](20-mid-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：点击劫持是透明 iframe 诱导点击。
2. 关键机制：浏览器根据响应头决定是否允许嵌入。
3. 注意点：meta CSP 不能设置 frame-ancestors。
4. 可追问时补充：敏感操作二次确认。

**常见追问**

- frame busting 脚本还能用吗？→ 不可靠，优先响应头。

### R16. `dialog` 元素有什么作用？和自定义弹窗相比有什么优势？

- **难度**: mid
- **标签**: dialog
- **来源倾向**: 新特性题

**答案**

原生 dialog 支持模态 / 非模态、top layer、背景 inert、Esc 关闭、`::backdrop`、表单返回值。相比自定义弹窗，减少 z-index、焦点和背景交互问题。

详见 [20-mid-qa Q27](20-mid-qa.md)、[40-coding H3](40-coding-handwritten.md)。

**口述模板（30–60 秒）**

1. 一句话结论：dialog 是浏览器原生弹窗能力。
2. 关键机制：showModal 进入 top layer，背景不可交互。
3. 注意点：仍要设置标题和合理默认焦点。
4. 可追问时补充：closedby 和 command 是较新增强。

**常见追问**

- `show()` 和 `showModal()` 区别？→ 前者非模态，后者模态。

### R17. Popover API 是什么？和 dialog 怎么选？

- **难度**: mid
- **标签**: Popover
- **来源倾向**: 2025 新特性

**答案**

Popover API 让元素通过 `popover` 属性成为浮层，可通过按钮声明式控制，并支持轻关闭。它适合菜单、提示卡片等轻量非模态 UI；需要阻断背景交互时用 modal dialog。

详见 [20-mid-qa Q28](20-mid-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：Popover 管轻量浮层，dialog 管任务型弹窗。
2. 关键机制：都可显示在 top layer。
3. 注意点：Popover 不自动提供菜单语义和完整键盘模型。
4. 可追问时补充：command/commandfor。

**常见追问**

- `popover="auto"` 和 `manual` 区别？→ auto 支持轻关闭和互斥，manual 需手动控制。

### R18. `command` 和 `commandfor` 是什么？

- **难度**: senior
- **标签**: Invoker Commands
- **来源倾向**: 2025 Web 平台更新

**答案**

它们让按钮声明式控制其他元素，例如打开 dialog 或切换 popover：

```html
<button commandfor="settings" command="show-modal">设置</button>
<dialog id="settings">...</dialog>
```

它在 2025 年末进入 Baseline，生产中要做特性检测和 JS 回退。

详见 [30-senior-qa Q22](30-senior-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：command 让 HTML 按钮直接调用目标元素能力。
2. 关键机制：commandfor 指目标，command 指动作。
3. 注意点：新特性需要兼容兜底。
4. 可追问时补充：可减少 JS 加载前不可交互的问题。

**常见追问**

- 它能完全替代 JS 吗？→ 只能覆盖内置和声明式场景，业务逻辑仍需 JS。

### R19. 什么是 Web Components？它由哪些部分组成？

3. 注意点：SSR、表单和可访问性要额外设计。
4. 可追问时补充：适合跨框架组件库。

**常见追问**

- Shadow DOM 是安全边界吗？→ 不是，只是封装。

### R20. 图片懒加载怎么实现？首屏图片能懒加载吗？

- **难度**: mid
- **标签**: 图片, 性能
- **来源倾向**: 性能优化高频

**答案**

现代浏览器可用 `loading="lazy"`；复杂需求可用 IntersectionObserver。首屏 LCP 图片不能懒加载，应尽早发现并可设置 `fetchpriority="high"`。

详见 [10-junior-qa Q18](10-junior-qa.md)、[20-mid-qa Q7/Q8](20-mid-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：非首屏图片懒加载，首屏关键图优先加载。
2. 关键机制：浏览器根据视口距离决定加载时机。
3. 注意点：图片要预留尺寸避免 CLS。
4. 可追问时补充：srcset/sizes 和现代格式。

**常见追问**

- 为什么懒加载后 CLS 变差？→ 图片没有提前占位。

### R21. `srcset` 和 `sizes` 是什么？

- **难度**: mid
- **标签**: 响应式图片
- **来源倾向**: 移动端 / 性能题

**答案**

`srcset` 提供候选图片，`sizes` 描述图片在不同视口下的显示宽度。浏览器结合 DPR 和布局宽度选择资源。

详见 [20-mid-qa Q8](20-mid-qa.md)、[40-coding H5](40-coding-handwritten.md)。

**口述模板（30–60 秒）**

1. 一句话结论：srcset 给候选，sizes 给布局宽度。
2. 关键机制：浏览器选择最合适的资源。
3. 注意点：sizes 写错会选错图。
4. 可追问时补充：picture 用于格式和裁剪切换。

**常见追问**

- 只写 srcset 不写 sizes？→ 对 `w` 描述符，浏览器会按默认 `100vw` 估算，可能下载过大。

### R22. 表单原生校验有哪些？前端校验能替代后端吗？

- **难度**: junior
- **标签**: 表单

`required`、`minlength`、`maxlength`、`pattern`、`min`、`max`、`step`、`type="email"` 等，以及 Constraint Validation API。前端校验只提升体验，不能替代后端校验。

4. 可追问时补充：错误提示的可访问性。

**常见追问**

- `novalidate` 后还能用 validity 吗？→ 可以，只是不显示浏览器默认提示。

### R23. 为什么 SSR 会出现 Hydration mismatch？和 HTML 有什么关系？

- **难度**: senior
- **标签**: SSR, Hydration
- **来源倾向**: React / Vue 高级题

**答案**

常见原因包括服务端和客户端数据不同、时间和随机数不同、浏览器专属分支，以及非法 HTML 嵌套导致浏览器自动修正 DOM。

详见 [30-senior-qa Q1](30-senior-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：服务端 HTML 和客户端预期树不一致就会 mismatch。
2. 关键机制：浏览器会修正非法 HTML。
3. 注意点：先检查嵌套合法性和确定性渲染。
4. 可追问时补充：时间、随机数、本地存储都要隔离。

**常见追问**

- `p` 里放 `div` 会怎样？→ 浏览器会提前关闭 p，DOM 结构改变。

### R25. SPA 页面切换时如何保证无障碍？

- **难度**: senior
- **标签**: SPA, a11y
- **来源倾向**: 中高级 React / Vue 工程题

更新 title、把焦点移到新页面主标题或主内容、必要时播报路由变化、恢复滚动和焦点，导航仍使用真实链接。

### R26. 讲讲你在项目中做过的 HTML / 可访问性 / 首屏优化（行为面试）

- **难度**: senior
- **标签**: 项目经历
- **来源倾向**: 高级岗位必备

**答案（STAR 模板）**

- **Situation**：例如活动页 LCP 偏高、表单转化率低、读屏用户无法完成下单
- **Task**：明确指标和目标，如 LCP 从 4s 降到 2.5s 内
- **Action**：
  - 用 Performance / RUM 定位瓶颈
  - LCP 图片改为 SSR 输出 + `fetchpriority`
  - 移除首屏 lazy，补尺寸
  - 表单补 label、autocomplete、错误关联
  - 加 CI a11y 扫描和组件约束
- **Result**：给出指标、业务影响和长期机制

**口述模板（2–3 分钟）**

1. 先讲业务影响和指标。
2. 再讲定位证据。
3. 然后讲具体 HTML 层改动。
4. 最后讲结果和防回归机制。

**常见追问**

- 如何证明是你的改动带来的收益？→ A/B 实验、灰度对比或前后同口径 RUM 数据。
