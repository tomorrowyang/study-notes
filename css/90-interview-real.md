### R1. 说一下 CSS 盒模型

- **难度**: junior
- **标签**: 盒模型
- **来源倾向**: 前端基础必问

**答案**

盒模型由 content、padding、border、margin 组成。`content-box` 的 width 只含内容；`border-box` 的 width 包含 content + padding + border。项目中通常全局设置 `box-sizing: border-box`。

详见 [10-junior-qa Q2](10-junior-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：盒模型决定元素尺寸如何计算。
2. 关键机制：两种 box-sizing 计算方式不同。
3. 注意点：margin 不计入 width。
4. 可追问时补充：外边距折叠。

**常见追问**

- 为什么推荐 border-box？→ 设定宽度后加 padding 不会意外撑大。

### R2. 什么是 BFC？如何触发？有什么作用？

- **难度**: mid
- **标签**: BFC
- **来源倾向**: 国内前端几乎必问

**答案**

BFC 是独立的块级布局区域。常用触发：`display: flow-root`、`overflow` 非 visible、浮动、绝对定位、Flex/Grid 等。作用：包含浮动、阻止 margin 折叠、自适应两栏布局。

详见 [20-mid-qa Q1](20-mid-qa.md)、[40-coding H5](40-coding-handwritten.md)。

**口述模板（30–60 秒）**

1. 一句话结论：BFC 是布局隔离区。
2. 关键机制：内部布局不影响外部。
3. 注意点：现代优先 flow-root。
4. 可追问时补充：Flex/Grid 为何没有 margin 折叠。

**常见追问**

- `overflow: hidden` 的副作用？→ 可能裁剪下拉框、阴影和定位元素。

### R3. 外边距折叠是什么？怎么解决？

- **难度**: mid
- **标签**: margin
- **来源倾向**: 高频基础

**答案**

普通流中垂直相邻块级元素 margin 会合并。可通过 padding、border、BFC、Flex/Grid 或改用 gap 解决。

详见 [20-mid-qa Q2](20-mid-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：普通流垂直 margin 会合并。
2. 关键机制：父子和兄弟都可能发生。
3. 注意点：Flex/Grid 子项不折叠。
4. 可追问时补充：负 margin 计算。

**常见追问**

- 左右 margin 会折叠吗？→ 不会。

### R4. CSS 选择器优先级怎么计算？

- **难度**: junior
- **标签**: 特异性
- **来源倾向**: 必问基础

**答案**

行内 > ID > 类 / 属性 / 伪类 > 元素 / 伪元素。相同特异性后写覆盖先写。`!important` 和 `@layer` 会改变层叠结果。`:where()` 特异性为 0。

详见 [10-junior-qa Q5](10-junior-qa.md)、[20-mid-qa Q6/Q7](20-mid-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：比较来源、层、特异性、顺序。
2. 关键机制：特异性按类别比较，不是简单相加。
3. 注意点：滥用 important 难维护。
4. 可追问时补充：@layer。

**常见追问**

- 11 个类能压过 1 个 ID 吗？→ 不能，类别优先比较。

### R5. Flex 和 Grid 有什么区别？

- **难度**: mid
- **标签**: Flex, Grid
- **来源倾向**: 必问布局题

**答案**

Flex 是一维布局，适合一行或一列内分配与对齐；Grid 是二维布局，适合同时控制行和列。常见组合：页面骨架用 Grid，组件内部用 Flex。

详见 [20-mid-qa Q8](20-mid-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：Flex 一维，Grid 二维。
2. 关键机制：Flex 内容驱动，Grid 轨道驱动。
3. 注意点：两者经常组合使用。
4. 可追问时补充：subgrid。

**常见追问**

- `flex: 1` 是什么？→ 常见展开为 `1 1 0%`，等分剩余空间。

### R6. 水平垂直居中有哪些方式？

- **难度**: junior
- **标签**: 居中
- **来源倾向**: 经典手写题

**答案**

Flex、Grid `place-items`、absolute + transform、absolute + inset + margin auto（定宽高）、table-cell（历史）。

详见 [40-coding H1](40-coding-handwritten.md)。

**口述模板（30–60 秒）**

1. 一句话结论：现代首选 Flex 或 Grid。
2. 关键机制：主轴和交叉轴同时居中。
3. 注意点：父元素需要高度。
4. 可追问时补充：未知宽高 transform 方案。

**常见追问**

- transform 居中为什么可能模糊？→ 可能出现亚像素渲染。

### R7. 什么是层叠上下文？为什么 z-index 不生效？

- **难度**: mid
- **标签**: 层叠上下文
- **来源倾向**: 实战高频

**答案**

层叠上下文是 z 轴上的独立渲染单元。z-index 只在同一上下文内比较。祖先的 `opacity`、`transform`、`filter`、定位 + z-index 等都可能创建上下文，导致子元素无法覆盖外部元素。

详见 [20-mid-qa Q4](20-mid-qa.md)、[40-coding H10](40-coding-handwritten.md)。

**口述模板（30–60 秒）**

1. 一句话结论：z-index 只能在同一上下文中比较。
2. 关键机制：子上下文整体参与父上下文排序。
3. 注意点：沿祖先排查。
4. 可追问时补充：Portal 和 top layer。

**常见追问**

- 怎么快速判断？→ DevTools 查看祖先属性，或临时移除 transform/opacity 验证。

### R8. 重排和重绘有什么区别？怎么优化？

- **难度**: mid
- **标签**: 性能
- **来源倾向**: 浏览器原理必问

**答案**

重排是几何信息变化导致重新布局；重绘是外观变化但不影响布局。优化：批量修改样式、读写分离、动画使用 transform / opacity、减少 DOM 层级和选择器复杂度。

详见 [20-mid-qa Q17/Q18](20-mid-qa.md)、[30-senior-qa Q2](30-senior-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：重排更贵，重绘次之，合成最便宜。
2. 关键机制：Layout → Paint → Composite。
3. 注意点：读写交错导致强制同步布局。
4. 可追问时补充：will-change。

**常见追问**

- 读取 offsetWidth 为什么慢？→ 若样式已失效，浏览器必须立即布局。

### R9. 为什么动画推荐用 transform？

- **难度**: mid
- **标签**: 动画
- **来源倾向**: 性能高频

**答案**

transform 和 opacity 通常只影响合成阶段，不触发布局；top / left / width 等往往每帧重排。

详见 [20-mid-qa Q18](20-mid-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：transform 更容易避开 Layout 和 Paint。
2. 关键机制：可在合成层处理。
3. 注意点：层过多也会卡。
4. 可追问时补充：prefers-reduced-motion。

**常见追问**

- will-change 能不能一直加？→ 不建议，会占用内存并改变层叠上下文。

### R10. 移动端适配方案有哪些？

- **难度**: mid
- **标签**: 移动端
- **来源倾向**: H5 必问

**答案**

viewport meta、响应式布局、rem / vw / clamp、媒体查询、容器查询、安全区、dvh、1px 细线处理、图片 srcset。

4. 可追问时补充：为什么不推荐整页缩放。

**常见追问**

- rem 方案需要 JS 吗？→ 传统动态根字号需要；现代可用 clamp/vw 减少依赖。

### R11. em、rem、vw 有什么区别？

- **难度**: junior
- **标签**: 单位
- **来源倾向**: 基础题

**答案**

em 相对当前元素字号，rem 相对根元素字号，vw 相对视口宽度。移动端高度建议用 dvh / svh。

详见 [10-junior-qa Q14](10-junior-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：参照对象不同。
2. 关键机制：em 会嵌套累乘。
3. 注意点：纯 vw 字号不利于用户缩放。
4. 可追问时补充：clamp。

**常见追问**

- 为什么不用 100vh？→ 移动端地址栏导致高度变化。

### R12. 如何实现 1px 细线？

- **难度**: mid
- **标签**: 移动端
- **来源倾向**: H5 经典题

**答案**

常用伪元素 + `transform: scaleY(0.5)`，也可用渐变或 border-image。原因是高 DPR 屏上 1 CSS 像素对应多个物理像素。

详见 [20-mid-qa Q31](20-mid-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：用缩放模拟物理 1px。
2. 关键机制：DPR 放大了 CSS 像素。
3. 注意点：父元素要相对定位。
4. 可追问时补充：设计系统统一 hairline。

**常见追问**

- 0.5px 可以吗？→ 部分环境支持，但跨平台不稳定。

### R13. sticky 定位为什么失效？

- **难度**: mid
- **标签**: sticky
- **来源倾向**: 实战题

**答案**

常见原因：没设 top、祖先 overflow 改变了滚动容器、父元素没有足够滚动空间、表格元素使用不当。

详见 [20-mid-qa Q28](20-mid-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：sticky 依赖阈值和滚动容器。
2. 关键机制：在最近滚动祖先中吸附。
3. 注意点：overflow 祖先最常见。
4. 可追问时补充：多个 sticky 的层级。

**常见追问**

- 表格表头吸顶怎么写？→ 对 `th` 设置 `position: sticky; top: 0`。

### R14. CSS Modules、CSS-in-JS、Tailwind 怎么选？

- **难度**: mid
- **标签**: 工程化
- **来源倾向**: 中高级工程题

**答案**

CSS Modules 编译期隔离、零运行时；CSS-in-JS 动态能力强但可能有运行时与 SSR 成本；Tailwind 开发效率高、依赖设计约束。按团队规模、主题需求和性能目标选择。

详见 [20-mid-qa Q23](20-mid-qa.md)、[30-senior-qa Q13/Q14](30-senior-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：没有银弹，按约束选择。
2. 关键机制：隔离方式和生成时机不同。
3. 注意点：运行时成本与可维护性。
4. 可追问时补充：零运行时 CSS-in-JS。

**常见追问**

- Tailwind 会不会让 HTML 难读？→ 会，需要组件封装和类名排序规范。

### R15. 如何实现暗黑模式？

- **难度**: mid
- **标签**: 主题
- **来源倾向**: 近年高频

**答案**

CSS 变量定义语义令牌，`prefers-color-scheme` 跟随系统，`data-theme` 支持手动切换，`color-scheme` 适配原生控件。首屏提前确定主题，避免闪烁。

**口述模板（30–60 秒）**

1. 一句话结论：变量 + 系统偏好 + 手动覆盖。
2. 关键机制：主题切换只改令牌。
3. 注意点：图片、阴影和对比度。
4. 可追问时补充：避免 FOUC。

**常见追问**

- 用户选择优先还是系统优先？→ 用户手动选择应优先，并持久化。

### R16. 什么是容器查询？和媒体查询有什么区别？

- **来源倾向**: 现代 CSS 高频

4. 可追问时补充：cqw 单位。

**常见追问**

- 能完全替代媒体查询吗？→ 不能，页面级断点和用户偏好仍用媒体查询。

### R17. `:has()` 是什么？能做什么？

3. 注意点：避免宽泛复杂匹配。
4. 可追问时补充：表单和卡片场景。

**常见追问**

- `:has()` 特异性？→ 取参数中最高特异性。

### R18. `@layer` 是什么？

- **难度**: mid
- **标签**: Cascade Layers
- **来源倾向**: 现代 CSS 工程题

**答案**

`@layer` 显式定义样式层的优先级，例如 reset、vendor、components、utilities。后声明的层优先，可减少特异性竞争和 `!important`。

详见 [20-mid-qa Q26](20-mid-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：@layer 管理样式层级。
2. 关键机制：层顺序先于特异性。
3. 注意点：未分层样式与 important 规则要理解。
4. 可追问时补充：第三方库放低层。

**常见追问**

- 为什么组件库适合用 layer？→ 让业务覆盖更可预测。

### R23. 弹窗被遮挡你怎么排查？

- **难度**: senior
- **标签**: 排障
- **来源倾向**: 实战场景题

**答案**

先区分层叠问题还是裁剪问题。沿祖先检查 transform、opacity、filter、z-index、overflow；检查 fixed 是否被 transform 祖先改变包含块。修复用 Portal、dialog top layer 或统一 z-index 令牌。

详见 [30-senior-qa Q21](30-senior-qa.md)。

**口述模板（30–60 秒）**

1. 一句话结论：先判断层叠还是 overflow 裁剪。
2. 关键机制：上下文和包含块。
3. 注意点：不要无限加 z-index。
4. 可追问时补充：z-index 规范。

**常见追问**

- 为什么挂到 body 就好了？→ 脱离原祖先的层叠上下文和裁剪边界。

### R24. 讲讲你做过的 CSS 性能优化或设计系统项目（行为面试）

- **难度**: senior
- **标签**: 项目经历
- **来源倾向**: 高级岗位必备

**答案（STAR 模板）**

- **Situation**：例如活动页 CLS 高、主题切换闪烁、组件库样式覆盖困难
- **Task**：明确指标，如 CLS < 0.1、主题切换无闪烁
- **Action**：
  - RUM 定位问题元素
  - 图片尺寸、字体 size-adjust、动态区块占位
  - 引入 Design Tokens 和 `@layer`
  - 视觉回归和 Stylelint 规则
- **Result**：指标变化、业务影响、长期机制

**口述模板（2–3 分钟）**

1. 先讲问题和业务影响。
2. 再讲定位方法和证据。
3. 然后讲 CSS 方案与取舍。
4. 最后讲结果和防回归。

**常见追问**

- 如何证明优化有效？→ 灰度或 A/B，对比同口径 RUM 数据。
