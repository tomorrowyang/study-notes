# Docker 系统设计 / 场景题

## 通用答题框架

1. 澄清目标与范围  
2. 约束（规模、RTO/RPO、安全合规、团队能力、成本）  
3. 总体方案（组件用缩进文本表达）  
4. 关键路径与数据流  
5. 瓶颈、降级、演进

### S1. 从零搭建中小团队 Docker 容器化基础设施

- **难度**: senior
- **标签**: 基础设施
- **来源倾向**: 大厂/中大厂架构面常见开放题

**澄清问题（面试时先问）**

- 团队规模、服务数量、是否多环境？  
- 是否已有 K8s？还是先单机/小集群？  
- 合规是否要求私有化仓库与扫描？  
- CI 用 GitLab 还是 GitHub 等？  

**参考方案**

```
开发者笔记本 (Docker Desktop/Engine + Compose)
        │  git push
        ▼
CI 构建集群 (BuildKit/buildx，与业务隔离)
        │  push digest
        ▼
Harbor (HA + 对象存储) ──扫描/签名──► 晋级策略
        │ pull
        ▼
运行环境：
  - 小型：Compose/单机或少量 VM + 反代
  - 成长：K8s + containerd
可观测：日志采集 + 指标 + 告警
```

**关键点**

- 构建与运行权限分离  
- 镜像治理（tag/digest/GC/扫描）  
- 环境配置分离（十二要素）  
- 先把开发体验（Compose）做好，再谈编排  

**口述模板（2–3 分钟）**

1. 先定规模：没有多节点痛点就不上 K8s。  
2. 标准链路：CI 构建 → Harbor → 环境拉取。  
3. 安全：非 root、扫描门禁、禁 sock 入业务。  
4. 观测与磁盘/日志治理一并设计。  
5. 演进：节点多了再迁 K8s，镜像工作流可复用。  

**扩展追问**

- Harbor 如何多机房复制？→ 复制策略与拉取就近。  
- 构建缓存如何共享？→ registry cache / 专用构建机磁盘。

### S2. 微服务在纯 Docker/Compose 下的部署架构（过渡期）

- **难度**: senior
- **标签**: 微服务, Compose

**澄清问题**

- 服务数量、是否需要滚动无停机？  
- 有状态服务几个？  
- 流量入口？  

**参考方案**

```
[Internet] → 宿主机 Nginx/Traefik
                ├─ api (replicas? 单机限制多)
                ├─ worker
                └─ 内网网：postgres/redis (volume)
```

要点：  

- 用 **profiles** 区分观测/调试组件  
- 依赖健康检查  
- 配置用 env/密钥文件权限  
- 明确单机 Compose **不是**高可用终态  

**口述模板（2–3 分钟）**

1. 入口反代 + 应用/数据网隔离。  
2. 健康检查与资源限制保稳定。  
3. 数据卷与备份。  
4. 说清何时必须迁编排。  

**扩展追问**

- 单机两实例如何滚动？→ 端口/上游切换或蓝绿目录；能力有限。

### S3. CI/CD 中的镜像构建安全架构（禁止滥用 docker.sock）

- **难度**: senior
- **标签**: CI, 安全

**澄清问题**

- 日均构建次数、语言栈、是否要多架构？  
- 能否接受专用构建集群成本？  

**参考方案**

```
Git push → CI worker (无特权)
              │ 远程 API
              ▼
        BuildKit 服务 / Kaniko / 独立构建节点
              │
              ▼
           Harbor ← 签名/扫描门禁
              │
              ▼
        部署系统只读拉取
```

对比：DinD / 挂 sock 的风险与适用（隔离构建机可受控使用）。

**口述模板（2–3 分钟）**

1. 业务流水线不持有宿主 Docker 特权。  
2. 构建集中化，缓存与密钥统一。  
3. 扫描签名不过不晋级。  
4. 部署身份与构建身份分离。  

**扩展追问**

- 密钥如何进构建？→ OIDC/短时凭证 + secret mount。

### S4. 镜像仓库高可用与治理

- **难度**: senior
- **标签**: Harbor, 治理

**澄清问题**

- 镜像体量、峰值拉取（发布窗口）？  
- 多地域？  

**参考方案**

```
Harbor 节点集群
  ├─ 核心 DB/Redis HA
  ├─ 对象存储（镜像 blob）
  ├─ 复制到备机房
  └─ GC 窗口与保留策略
发布期：节点预热 / 限流 / 镜像缓存代理
```

**口述模板（2–3 分钟）**

1. 元数据与 Blob 分离，后端对象存储。  
2. 权限项目化，扫描强制。  
3. 发布防雪崩：预热与复制。  
4. GC 与不可变 tag 策略。  

**扩展追问**

- 如何防 tag 被覆盖？→ immutable 项目、签名、权限。

### S5. 有状态 MySQL/Postgres 容器化方案（慎用题）

- **难度**: senior
- **标签**: 有状态

**澄清问题**

- RPO/RTO？读写规模？是否允许主从？  
- 团队有没有 DBA？  

**参考方案（若必须容器化）**

```
调度粘性节点（或固定 VM）
  └─ DB 容器
       └─ 高性能卷（云盘/本地 SSD）
备份：逻辑备份 + 卷快照
切换：主从或云托管更优
监控：连接数、延迟、磁盘、复制位点
```

更优默认建议：**托管数据库**；容器化要证明运维闭环。

**口述模板（2–3 分钟）**

1. 先劝托管。  
2. 若自建：盘、备份、监控、故障切换缺一不可。  
3. 不要把数据放 overlay 可写层。  
4. 给出演进：Operator/云服务。  

**扩展追问**

- 本地 SSD 节点挂了怎么办？→ 副本/重建/备份恢复演练。

### S6. 灰度发布：只有 Docker 时怎么做？

- **难度**: senior
- **标签**: 发布

**澄清问题**

- 流量是否经网关？是否会话有状态？  
- 单机还是多机？  

**参考方案**

```
网关加权上游：
  v1 实例 90% → 镜像@digestA
  v2 实例 10% → 镜像@digestB
观测错误率/延迟 → 调权或回滚切回 digestA
```

单机 Compose：双端口 + 反代权重；多机需统一控制面（往往已经该上 K8s/服务网格）。

**口述模板（2–3 分钟）**

1. 灰度本质是流量切割 + 可回滚产物。  
2. Docker 提供不可变产物，网关做权重。  
3. 指标驱动晋级。  
4. 规模上来用专业发布系统。  

**扩展追问**

- DB 不兼容迁移如何灰度？→ expand/contract 迁移模式。

### S7. 多租户 CI 构建的隔离设计

- **难度**: senior
- **标签**: 多租户, 安全

**澄清问题**

- 是否不可信代码（外部 PR）？  
- 是否需要网络访问外网？  

**参考方案**

```
不可信构建：
  强隔离节点池 / Kata / 独立 VM
  网络默认出站限制
  无密钥或短时下发
  超时与资源硬限制
可信构建：
  共享 BuildKit 缓存（按租户分 cache namespace）
```

**口述模板（2–3 分钟）**

1. 信任模型决定隔离强度。  
2. 资源/网络/密钥三维限制。  
3. 缓存要防跨租户投毒。  
4. 成本与安全权衡公开讲。  

**扩展追问**

- 缓存投毒如何防？→ 缓存键隔离、只缓存可信主分支。

### S8. 边缘/单机柜交付：离线镜像与更新

- **难度**: mid
- **标签**: 交付

**澄清问题**

- 现场有无外网？更新窗口？回滚要求？  

**参考方案**

```
中心构建 → 导出镜像包 (docker save / 专用包)
现场导入 → compose up
版本清单：digest 列表 + compose 文件
回滚：导入旧包并切清单
```

**口述模板（2–3 分钟）**

1. 离线以包为产物单位。  
2. 清单锁定 digest。  
3. 演练导入与回滚。  
4. 注意磁盘与校验和。  

**扩展追问**

- 密钥与证书现场如何注入？→ 现场密封配置，不进镜像包。

### S9. 日志与磁盘永不打满的平台规范

- **难度**: mid
- **标签**: 可观测, 治理

**澄清问题**

- 日志量级、是否要长期审计？  

**参考方案**

```
容器 stdout
  → 节点 logging driver（轮转）
  → Agent → 集中式存储（Loki/ES）
策略：节点本地只保留短期；告警磁盘/inode；大事件限流
```

**口述模板（2–3 分钟）**

1. 本地轮转兜底，中心存储为主。  
2. 应用禁止狂写容器层文件。  
3. 告警与自动清理分级。  

**扩展追问**

- 多行 Java 栈如何解析？→ 采集端 multiline 配置。

### S10. 从 Docker 单机迁到 Kubernetes 的演进路线

- **难度**: senior
- **标签**: 演进, K8s

**澄清问题**

- 迁移窗口、服务依赖、团队技能？  

**参考方案（阶段）**

```
阶段 A：镜像与仓库规范化（已容器化）
阶段 B：接入 K8s，先无状态服务
阶段 C：配置/密钥/探针/资源标准化
阶段 D：有状态与作业、自治运维
阶段 E：逐步下线 Compose 生产（保留本地开发）
```

**口述模板（2–3 分钟）**

1. 先标准化镜像与 CI，迁移成本最低。  
2. 无状态先行。  
3. 开发仍可用 Compose。  
4. 平台能力（观测/发布）同步建设。  

**扩展追问**

- 网络策略与原 Docker 网络如何映射？→ Service/NetworkPolicy 概念对照。
