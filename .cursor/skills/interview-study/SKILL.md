# Interview Study（面试向主题学习包）

用户说「我想学 X」时：在**工作区根目录**创建 `<主题>/`，一次性生成完整 Markdown 学习包，供边看边学边记。目标对齐**国内互联网高级工程师面试**（深度原理 + 对比 + 场景 + 口述）。

## 触发与范围

- 触发：我想学 / 学习 / 准备面试 / 刷题 + 主题名（docker、react、vue…）
- 岗位：不限；按主题自适应（前端/后端/DevOps/中间件等）
- 语言：中文为主，关键概念保留英文术语（如 Reconciliation、cgroup）
- 代码：按主题选型（TS/JS、Go、Shell、YAML 等），示例短而可讲
- **不要**把问题和答案拆成两份；每题下方紧跟答案与口述提示

## 执行流程（必须按序）

1. **规范化主题名**：小写、短横线文件夹名（`react`、`docker`、`system-design`）。若已存在同名目录，询问覆盖 / 增量补充 / 换名。
2. **快速调研（生成前）**：用 WebSearch 检索该主题近 1–2 年高频面试题与版本变化；有 Context7/官方文档 MCP 时优先查官方概念。把真实题融入 `90-interview-real.md`，并在答案中注明常见追问。
3. **建目录并写全套文件**（见下方结构）。默认 **4B 完整包**：知识点 Q&A 合计约 **80–150 题**（含各难度），外加手写题与系统设计题。
4. **写完后**用中文简短汇报：目录路径、文件清单、建议阅读顺序、如何继续补充。

生成阶段默认**一次性写完整包**；除非用户明确要求「先大纲后正文」或「每次只出几题」。

## 目录结构（每个主题固定）

```
<topic>/
├── 00-roadmap.md              # 知识地图、学习顺序、面试重点、自测清单
├── 10-junior-qa.md            # 初级：概念与常用 API/命令
├── 20-mid-qa.md               # 中级：原理、对比、常见坑
├── 30-senior-qa.md            # 高级：源码/底层、性能、排查、架构取舍
├── 40-coding-handwritten.md   # 手写 / 现场编码 / 读代码改 bug
├── 50-system-design.md        # 系统设计 / 方案设计 / 场景题
├── 90-interview-real.md       # 真实/高频面试题汇编（带来源倾向说明）
└── PROGRESS.md                # 进度勾选 + 薄弱点记录
```

模块特别多时可另增 `21-<子模块>-qa.md`（如 `21-hooks-qa.md`），但必须在 `00-roadmap.md` 链过去。控制单文件可读性：单文件建议 ≤ ~120 题；超出则拆文件。

## 难度分层标准

| 文件 | 对准级别 | 题目应覆盖 |
|------|----------|------------|
| `10-junior-qa.md` | 能用 | 是什么、怎么用、常用参数/API、基础命令 |
| `20-mid-qa.md` | 能讲清 | 为什么、和同类对比、生命周期/执行机制、常见故障 |
| `30-senior-qa.md` | 能扛追问 | 底层/源码路径、性能与容量、稳定性、权衡、线上排查思路 |

高级题必须包含至少一类：**原理深挖 / 对比选型 / 故障排查 / 性能优化 / 生产实践**。

## 单题格式（问答同页，强制）

每题使用以下模板（可直接复制）：

```markdown
### Q<编号>. <问题>（英文关键词可附）

- **难度**: junior | mid | senior
- **标签**: <如 渲染 / 网络 / 存储>

**答案**

<直接写完整答案；先结论后展开。中英术语对照写在首次出现处。>

**口述模板（30–60 秒）**

1. 一句话结论：…
2. 关键机制/步骤：…
3. 对比或注意点：…
4. 可追问时补充：…

**常见追问**

- …？→ 简答…
```

手写题、系统设计题用各自文件内的变体模板（见 [templates.md](templates.md)）。

## 各文件职责

### `00-roadmap.md`

- 一句话：学完要对齐什么面试画像
- 知识地图（树状或分层列表）
- 建议阅读顺序（链到各 md）
- 「高级面试必打点」10–20 条
- 与相邻技术栈关系（如 React ↔ 浏览器原理、Docker ↔ Linux/K8s）

### `10/20/30-*-qa.md`

- 按主题逻辑分节（不要随机堆题）
- 覆盖广度 + 高级深度；避免只抄官方文档目录
- 适当给短代码/命令；解释「为什么这样写/这样配」

### `40-coding-handwritten.md`

- 前端：Hooks/组件、防抖节流、深拷贝、并发请求、虚拟列表等
- 后端：并发、缓存、限流、算法在业务中的变形
- DevOps：Dockerfile 多阶段、排障脚本、Compose/网络题
- 每题：题干 → 参考实现要点 → 面试官看什么 → 口述如何讲思路

### `50-system-design.md`

- 用「澄清需求 → 约束 → 方案 → 瓶颈 → 演进」结构
- 每题附：可画的模块图文字版、关键指标、取舍
- 按主题出 5–12 道场景题即可（质量优于堆数量）

### `90-interview-real.md`

- 优先收录检索到的高频/真实问法；可改写为更清晰的中文题干
- 每题标注：`来源倾向`（如「大厂前端高频」「社区 2024–2025 汇总」），无法核实具体公司时**不要编造公司名与年份细节**
- 答案同样用「答案 + 口述模板 + 常见追问」
- 与 10/20/30 重复的题可更短，并链接「详见 xx 文件 Qn」

### `PROGRESS.md`

- checklist：各文件完成度
- 「薄弱点」空白列表供用户填
- 「下次复习」三行占位

## 质量红线

- 对准高级：少「背定义」，多「机制 + 对比 + 场景 + 怎么讲」
- 禁止考试式「仅题目卷 + 仅答案卷」
- 禁止空洞废话与假大空项目吹嘘；示例要具体
- 版本相关内容写清适用版本（如 React 18+、Docker 某特性）
- 安全/违法内容不涉及攻击利用细节；排障讲防御与诊断思路即可
- 先方案后改代码的用户规则：若用户只要改 skill/模板，先简述再改；**生成某个主题学习包时直接生成**（用户已用「我想学 X」授权）

## 增量与复习指令

用户后续可能说：

| 用户意图 | 动作 |
|----------|------|
| 补充 XX 模块 | 增文件或向对应难度文件追加 Q，并更新 roadmap/PROGRESS |
| 再来一批真题 | 重新检索后追加到 `90-interview-real.md` |
| 加口述/加追问 | 给已有题补全口述模板与追问 |
| 按子方向加深（如 React 性能） | 新开 `31-performance-qa.md` 并挂到 roadmap |
