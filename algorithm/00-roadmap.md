# 数据结构与算法学习路线（前端面试向）

## 面试画像

国内大厂的前端面试中，算法题几乎是每一轮的「固定环节」：一面通常 1 道简单或中等题，二面 / 三面 1–2 道中等题，偶尔有困难题。和后端岗位相比，前端的算法面试有几个特点：

- **题目范围**：以 LeetCode **Hot 100 / 剑指 Offer** 的简单和中等题为主，高频题型集中在数组、字符串、链表、二叉树、哈希、双指针、滑动窗口、栈、DFS / BFS、回溯、动态规划
- **前端特色题**：结合前端场景考算法，例如虚拟 DOM diff、最长递增子序列（Vue 3 diff）、扁平数组转树、LRU 缓存、任务调度（最小堆）、并发控制、版本号比较、大数相加
- **评估重点**：能否在 20–30 分钟内**说清思路 → 写出无 bug 的代码 → 分析复杂度 → 处理边界**；高级岗还会追问优化和变体
- **语言**：用 JavaScript / TypeScript 作答

高级岗典型问法：

> 「先说思路，再写代码」「时间和空间复杂度是多少？能优化吗？」「如果数据量很大 / 数据是流式的怎么办？」「Vue 3 的 diff 为什么要用最长递增子序列？」「React 的调度器为什么用最小堆？」「LRU 怎么做到 O(1)？」

## 学习现状说明（截至 2026-10）

| 项目 | 说明 |
|------|------|
| 题库 | LeetCode Hot 100 仍是国内面试最常用的参考范围；剑指 Offer 题目在国内面经中仍高频出现 |
| 语言 | JS / TS 作答被普遍接受；注意 JS 没有内置的堆、有序集合，需要手写或说明 |
| 形式 | 在线编辑器（无自动补全），部分公司要求能运行通过测试用例 |
| AI 时代 | 部分公司开始允许或考察使用 AI 工具，但算法基础和代码阅读、调试能力仍是重点考察内容 |

> 面试形式因公司和团队而异，以实际面试为准。

## 高级岗必会点（18 条）

1. 能快速分析时间 / 空间复杂度，知道 JS 中常见操作的复杂度（`shift` 是 O(n)、`Map` 的增删查是 O(1)）
2. **双指针和滑动窗口**的模板与适用条件
3. **哈希表**换时间：两数之和、计数、去重
4. 链表的基本操作：反转、快慢指针（环、中点）、虚拟头节点
5. 二叉树的**递归思维**：前中后序、层序；用「子问题的返回值」解题
6. 二分查找的**边界处理**（左闭右闭 vs 左闭右开）和二分答案
7. 快速排序和归并排序的手写与复杂度；排序的稳定性
8. **单调栈 / 单调队列**的适用场景（下一个更大元素、滑动窗口最大值）
9. **堆**的实现与 Top K；为什么 React 调度器用最小堆
10. **回溯**的模板：选择、递归、撤销；剪枝
11. **动态规划**的步骤：状态定义 → 转移方程 → 初始化 → 遍历顺序；常见模型（子序列、背包、股票）
12. 图的 BFS / DFS、**拓扑排序**、并查集
13. **LRU 缓存**的 O(1) 实现（Map 的插入顺序 / 哈希 + 双向链表）
14. **最长递增子序列**的 O(n log n) 解法，以及在 Vue 3 diff 中的用途
15. 虚拟 DOM diff 的复杂度从 O(n³) 降到 O(n) 的假设
16. Trie 的实现与前缀搜索
17. 扁平数组转树的 O(n) 解法、树的遍历与查找
18. 面试作答流程：澄清 → 举例 → 思路与复杂度 → 编码 → 测试边界
