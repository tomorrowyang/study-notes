> 根据近年公开面经和技术社区讨论整理，`来源倾向`表示这类题目常出现的场景，不代表某公司的固定题库。答案为要点，详细内容见对应链接。前端算法面试以 LeetCode Hot 100 的简单和中等题为主，下面按出现频率较高的题目整理。

### R1. 两数之和 / 三数之和

- **来源倾向**: 一面、高频
- **难度**: 初级 / 中级

**答案**

- 两数之和：哈希表记录「值 → 下标」，先查后存，O(n)
- 三数之和：排序 + 固定一个数 + 对撞双指针，三处去重，O(n²)

详见：[10-junior-qa.md Q6](./10-junior-qa.md)、[20-mid-qa.md Q9](./20-mid-qa.md)

**口述模板（30–60 秒）**

1. **一句话结论**：两数之和用哈希表，三数之和用排序加双指针。
2. **关键机制**：哈希表把查找降到 O(1)；排序后双指针根据和的大小移动。
3. **对比或注意点**：三数之和要在三个位置跳过重复值。
4. **可追问时补充**：有序数组的两数之和可以用双指针做到 O(1) 空间。

### R2. 无重复字符的最长子串

- **来源倾向**: 一面、高频
- **难度**: 中级

**答案**

- O(n)

### R4. 反转链表 / K 个一组反转

- **来源倾向**: 一面 / 二面、高频
- **难度**: 初级 / 中级

**答案**

- 迭代：prev、cur，先保存 next
- K 个一组：虚拟头节点；找到第 k 个节点；反转时 prev 初始化为下一组的头

详见：[10-junior-qa.md Q12](./10-junior-qa.md)、[20-mid-qa.md Q17](./20-mid-qa.md)

**口述模板（30–60 秒）**

1. **一句话结论**：用 prev 和 cur 两个指针逐个反转。
2. **关键机制**：修改指针前先保存 next。
3. **对比或注意点**：K 个一组时，不足 k 个的部分保持原样。
4. **可追问时补充**：虚拟头节点让第一组和其他组的处理一致。

### R9. 手写快速排序 / 归并排序

- **来源倾向**: 一面、高频
- **难度**: 初级

**答案**

- 快排：随机基准、partition、递归；平均 O(n log n)，不稳定
- 归并：分治 + 合并；稳定，O(n) 空间
- 大量重复元素：三路快排

详见：[10-junior-qa.md Q22–Q23](./10-junior-qa.md)、[40-coding-handwritten.md H7](./40-coding-handwritten.md)

**口述模板（30–60 秒）**

1. **一句话结论**：快排是选基准分区后递归，归并是递归排序两半再合并。
2. **关键机制**：快排平均 O(n log n)，随机基准避免退化。
3. **对比或注意点**：快排不稳定、原地；归并稳定、需要 O(n) 空间。
4. **可追问时补充**：V8 的 sort 使用 TimSort，是稳定的。

### R11. LRU 缓存

- **来源倾向**: 二面 / 三面、前端高频
- **难度**: 中级

**答案**

- Map 的插入顺序：get 时删除后重新插入，超出容量删除第一个键
- 哈希表 + 双向链表 + 哨兵节点（不依赖 Map 顺序）
- 应用：keep-alive 的 max、请求缓存

详见：[20-mid-qa.md Q7](./20-mid-qa.md)、[40-coding-handwritten.md H1](./40-coding-handwritten.md)

**口述模板（30–60 秒）**

1. **一句话结论**：LRU 用哈希表加双向链表实现 O(1)。
2. **关键机制**：哈希表负责查找，链表维护使用顺序，访问时移到头部。
3. **对比或注意点**：JS 中 Map 保持插入顺序，可以更简洁地实现。
4. **可追问时补充**：链表节点要保存 key，淘汰时才能从哈希表中删除。

### R13. 爬楼梯 / 打家劫舍 / 最大子数组和

- **来源倾向**: 一面
- **难度**: 初级 / 中级

**答案**

### R14. 最长递增子序列（及其在 Vue 3 中的应用）

- **来源倾向**: 二面 / 三面、前端特色
- **难度**: 中级 / 高级

**答案**

- O(n²) DP；O(n log n) 贪心 + 二分
- Vue 3 diff：对新节点在旧列表中的位置求 LIS，LIS 中的节点不移动；需要记录前驱还原序列

详见：[20-mid-qa.md Q22](./20-mid-qa.md)、[30-senior-qa.md Q2–Q3](./30-senior-qa.md)、[40-coding-handwritten.md H5](./40-coding-handwritten.md)

**口述模板（30–60 秒）**

1. **一句话结论**：LIS 可以用贪心加二分做到 O(n log n)。
2. **关键机制**：维护每个长度的最小结尾，每个数二分找到替换位置。
3. **对比或注意点**：求具体序列要记录前驱并回溯。
4. **可追问时补充**：Vue 3 用 LIS 找出不需要移动的节点，使移动次数最少。

### R20. 扁平数组转树 / 树转扁平

- **来源倾向**: 一面 / 二面、前端特色
- **难度**: 中级

**答案**

- Map 记录 id → 节点，一次遍历挂到父节点上，O(n)
- 父节点后出现时先占位；孤儿节点和自引用的处理
- 树转扁平：DFS / BFS 记录 parentId

详见：[30-senior-qa.md Q20](./30-senior-qa.md)、[40-coding-handwritten.md H6](./40-coding-handwritten.md)

**口述模板（30–60 秒）**

1. **一句话结论**：用 Map 记录 id 到节点的映射，一次遍历完成。
2. **关键机制**：遍历时把节点挂到父节点的 children 上。
3. **对比或注意点**：双重循环查找子节点是 O(n²)。
4. **可追问时补充**：要处理父节点不存在和自引用等异常数据。

### R25. 虚拟 DOM diff 的复杂度和算法

- **来源倾向**: 二面 / 三面、前端特色
- **难度**: 高级

**答案**

- 通用树编辑距离 O(n³)；三个假设（同层比较、类型不同直接替换、key）降到 O(n)
- React：单向遍历 + Map + lastPlacedIndex
- Vue 3：双端预处理 + LIS

详见：[30-senior-qa.md Q1–Q2](./30-senior-qa.md)

**口述模板（30–60 秒）**

1. **一句话结论**：框架通过三个假设把 diff 从 O(n³) 降到 O(n)。
2. **关键机制**：只比较同层、类型不同直接替换、用 key 识别列表中的节点。
3. **对比或注意点**：React 单向遍历，Vue 3 用双端预处理和最长递增子序列。
4. **可追问时补充**：Vue 3 的方案保证列表重排时移动次数最少。
